# Agent Note: 十进制数据仅在具有 Git 引用语法时参与提交查找

Status: implemented

[English](2026-10-22-decimal-repository-reference-candidates.md) | 中文

## 问题

十进制字节数可能碰巧与本地可用提交的缩写名称一致。把所有看似十六进制的 token 都交给 Git 判定，会让未改动的依赖锁文件在本地对象数据库新增无关提交后无法通过引用校验。带引号的普通标识和日期也存在同样的歧义。

## 决策

仓库引用检查器把没有标签的十进制 token 视为数据。十进制 token 仅在可识别的 Git 引用语法中成为候选：提交或修订标签、Git 修订 URL 路径、受支持的 Git 命令操作数，或修订后缀。含十六进制字母的 token 沿用既有检测。候选查找仍要求恰好匹配一个可用的 commit 类型对象；blob、tree、歧义前缀、缺失对象和长摘要保留既有处理方式。

候选提取与逐行报告使用同一个按出现位置判定的分类器。一行中的明确引用不会让另一处相同数值的普通字节数也被报告。候选上下文限于当前行；这不是完整的 shell 程序解析器，也不解析任意自然语言引用。

[一次对象列表](../process/2026-10-12-local-gate-speedups.zh.md) 仍拥有前缀解析性能和歧义规则的决策。分类器不获取历史，也不修改本地对象数据库。

## 备选方案

**排除依赖锁文件。** 锁文件可能包含真实的固定 Git URL。整类文件豁免会隐藏该引用，也无法避免其他文件中的相同数字碰撞。

**忽略所有十进制提交名称。** Git 允许纯十进制的缩写对象名。明确的数字 Git 引用仍需校验，不应因其拼写形式而被忽略。

**继续把对象存在视为充分依据。** 对象存在只能证明 token 可以解析，不能证明某个字节数或日期在引用该对象。检查结果仍会依赖无关的获取操作与本地历史。

**完整解析每种文件格式。** 维护中的输入包括正文、源码、配置和符号链接目标。为每种输入维护格式专属解析器会增加大量策略与维护成本，仍无法解释没有标签的十进制正文。

## 影响

数字数据不会仅因本地存在匹配提交而成为禁止的引用。没有可识别 Git 引用语法的纯十进制正文被明确允许。包含十六进制字母的提交名和明确数字 Git 引用仍受拒绝策略约束；没有新增路径豁免，也没有修改锁文件。

真实临时 Git 仓库覆盖纯数字前缀提交、相同数值分别作为数据和引用的出现位置、对象类型、歧义，以及部分克隆中的缺失对象。仓库级命令基于实际本地对象数据库检查未改动的锁文件。
