# Agent Note：MCP 工具发现拒绝重复 cursor

Status: implemented

[English](2026-08-21-mcp-tools-list-repeated-cursor.md) | 中文

## 问题

MCP 工具发现会持续取尽 `tools/list`，直到服务器省略 continuation cursor。服务器重复返回非空 cursor 时，获取循环会一直存活，因此初始激活永远无法结算，后续 `notifications/tools/list_changed` 同步也会无限占用其串行链。空页面可以绕过重复工具检查，并在既不 resolve 也不 reject 的情况下产生无界协议流量。

[MCP client 决策](../feature/2026-07-07-mcp-client-plugin.md)拥有发现与世代替换。本 Agent Note 只拥有发现期间的异常分页。

## 决策

每个获取阶段都会记录服务器返回的非空 continuation cursor。该阶段再次收到已经出现过的 cursor 时，同步会在下一次请求使用它之前，以带服务器名称的错误拒绝。诊断会指出协议故障，但不回显不可信 cursor。

重复 cursor 拒绝仍属于获取阶段失败。新世代不会安装，上一世代保持注册。空 cursor 仍会结束分页，也不会用任意页数上限拒绝持续产生不同 cursor 的有限服务器。

## 考虑过的替代方案

- **限制页面数量。** 固定上限也会拒绝合法的有限工具目录，而且无法指出导致进度不可能继续的异常服务器状态。
- **增加同步超时。** 超时能限制墙钟时间，却仍允许无谓请求一直持续到期限，并引入与分页正确性无关、随部署变化的策略。
- **依赖 MCP SDK 缓存页面。** 工具发现有意发送无缓存请求，使输出验证与世代归属保留在本包；进度不变量也必须由本包拥有。

## 后果

无效 MCP 服务器会使发现失败，而不是挂住激活或后续同步。合法分页与工具名称不变；该防护只在一个获取阶段的存续期间为每个已访问页面保留一个字符串。

## 测试

MCP client 包测试会先安装一个稳定世代，再提供两个带相同 continuation cursor 的空页面。测试钉住第二次响应之后的拒绝，并证明稳定工具仍保持注册。既有的不同 cursor 分页场景继续钉住正常的多页发现。
