# Agent Note: 队列编辑确认响应只属于一个草稿版本

Status: implemented

[English](2026-10-22-queued-message-edit-acknowledgements.md) | 中文

## 问题

QueueDock 在异步队列编辑等待期间保持内联编辑器可编辑。成功时无条件关闭编辑器会丢弃提交后输入的文字，而 Host 只保存了提交时的文字。禁用操作按钮也无法阻止编辑器的 Enter 处理函数再次提交修改。

## 决策

提交时捕获不可变的编辑对象，仅当请求成功时该对象仍是当前版本，才清除本地编辑状态。每次输入变更都创建新版本，即使用户最终改回已提交的文字。后续编辑保留给显式保存，不静默提交。

组件拥有的同步标记确保同一时间最多一次队列修改，直到其 Promise 结束；渲染的繁忙状态仍用于按钮和展开指示。失败时释放标记，保留最新草稿以便重试。显式取消和权威队列行退休保留既有行为，请求结束不会恢复编辑器。

## 备选方案

- 保存期间禁用输入：可以避免确认响应竞争，但会在整个网络等待期间打断编辑。
- 只比较当前文字与已提交文字：用户先改动再改回相同内容时，无法保留版本身份。
- 仅用 React 繁忙状态拦截：下一次渲染前的重复键盘操作仍未受保护。
- 自动保存后续编辑：改变显式保存意图，可能在未经再次确认时修改排队消息。

## 影响

修复仅位于队列 UI 所有者中。Host 队列语义、公共类型、RPC 字段、Session 事件和持久化格式不变。后续草稿仍是本地状态，仍可取消，也可在队列行退休时移除；这不提供刷新后的草稿持久化。

组件回归测试覆盖后续版本、重复保存、失败与重试、取消和退休。录制的 queue-actions 浏览器场景延迟真实 Host 编辑响应，保留后续输入，并验证显式保存的文字进入持久化用户消息。
