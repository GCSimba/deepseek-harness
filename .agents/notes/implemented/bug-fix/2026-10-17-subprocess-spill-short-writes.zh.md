# Agent Note: 完整写入子进程 spill 文件

Status: implemented

[English](2026-10-17-subprocess-spill-short-writes.md) | 中文

## 问题

成功返回的 `writeSync` 调用可能只写入少于请求数量的字节。忽略该计数会丢失输出，同时保留被消费方描述为完整输出的 spill 路径。仅捕获异常无法发现这种丢失。

## 决策

`OutputCollector` 使用 Node 的 `writeFileSync` 在现有描述符上追加缓冲区。该内置函数补全部分写入，不会重新打开、截断或关闭该描述符。后续写入错误沿用既有的[尽力而为 spill 策略](../architecture/2026-09-22-fatal-diagnostics-and-crash-reports.zh.md)：丢弃不完整的 spill、报告一次，并保留有界内存尾部。

## 考虑过的替代方案

**单独实现写入循环。** Node 已负责调用方持有的描述符上的缓冲区偏移与完整写入。本地循环会重复这一机制。

**丢弃每次短写。** 部分写入可以成功补全；将写入进展视为失败会不必要地移除可恢复的输出。

## 验证

真实文件测试在缓存回放、首次溢出和后续追加期间注入部分写入。它们覆盖重复短写、UTF-8 字节、封闭描述符前后的读取，以及后续 `ENOSPC` 引发的文件删除和单次报告。每项测试都会恢复原生文件系统函数，并在删除其私有目录前关闭描述符。故障注入不能确定真实磁盘耗尽的发生频率或断电持久性。

## 影响

公布的 spill 保留其上限内接收的每个字节。部分写入会增加补全缓冲区所需的写入次数；持续错误保持原有的仅保留尾部行为。公共类型、文件命名、字节上限、诊断和 spill 生命周期均不改变。工具输出 spill 策略与致命故障诊断决策继续有效，均未被取代。
